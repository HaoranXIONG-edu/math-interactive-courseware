# 初中数学学案（.docx）无损优化与交互式动态课件（HTML）开发项目经验总结

> **来源项目**：会话 `a42f8002-91c2-4f4a-9872-7b9976a35cfd`（《2.1 认识反比例函数》《2.2.1 反比例函数的图象（1）》）及本节《2.2.2 反比例函数的图象（2）》全流程沉淀  
> **核心目标**：建立一套可复用、零破版、高颜值、强教学契合度的**“原版 Word 学案原地无损精修 + 希沃大屏交互式 HTML 动态精讲课件”**标准化研发规范。

## 第一部分：Word 学生学案（`.docx`）原地无损精修规范

在迭代《2.1 认识反比例函数》与《2.2.1 反比例函数的图象（1）》学案的过程中，我们经历了从“使用 `python-docx` 新建无边框表格重排（导致页面边距改变、字号缩水、页数膨胀、圆角文本框丢失）”到**“基于 `word/document.xml` 的原地无损替换（In-Place XML Patching）”**的关键技术跨越。核心经验总结如下：

### 1. 严守“原地无损修改（In-Place XML Patching）”铁律
- **保留原文档骨架**：严禁抛弃原文档重新生成 `.docx`。必须直接解压原 `.docx` 模板，在 `word/document.xml` 上作定点替换，100% 保留原文档的页面边距（上下 `15.0mm`、左 `20.0mm`、右 `15.0mm`）、学校抬头页眉、段落行距（`1.5倍行距`、`w:line="360"`）、字号（四号 `12pt`，即 `w:sz="24"`）及首行缩进。
- **保留特殊浮动图形与圆角归纳框**：
  - 原学案中的归纳总结框通常采用 Word 原生圆角矩形文本框（`<mc:AlternateContent>` 包含 `wps:txbx` 与 `v:roundrect`/`v:textbox` 双分支）。
  - 修改圆角框内文字与公式时，**必须同时更新 `mc:Choice`（DrawingML）与 `mc:Fallback`（VML）两个分支中的 `<w:txbxContent>`**，并删除 `<v:roundrect>` 上的 `o:gfxdata` 属性（防止 Word 优先使用缓存的旧版 Base64 图形数据导致修改不生效）。
- **彻底清理圆角浮动框下方的“幽灵残留段落”**：
  - 教师在复用上一节学案模板制作新学案时，常将一个不透明白底的浮动文本框（`<wp:anchor behindDoc="0">`）直接盖在旧题干段落上方（例如《2.2.2》中问题1归纳框与 $k$ 的几何意义框下方，隐藏了《2.2.1》残留的两段“问题2：在下面的坐标系中画出反比例函数的图象”）。
  - 优化学案时必须遍历全篇段落，精准清空被浮动框遮挡的废弃模板残留段落，避免移动文本框或转换格式时“鬼影重现”。

### 2. 彻底清除 MathType 遗留 WMF 对象，100% 升级原生 OMML 公式
- **痛点**：老旧学案中的分式（如 $y=\frac{4}{x}$）、下标（如 $y_1, y_2, S_{\triangle QAO}$）、上标（如 $m^2+1$）大量混用模糊的 MathType OLE 内嵌矢量图（`<w:object>` + `image*.wmf`）与纯文本斜杠，不仅打印发虚，且无法与正文基线对齐。
- **解决方案**：
  - 编写 XML 转换器，将文档中所有 `<w:object>` 节点**全部剥离（实现 `objs = 0`）**，替换为与正文同字号（四号 `12pt`）的 Word 原生公式 `<m:oMath>`（分式 `<m:f>`、上下标 `<m:sSub>`/`<m:sSup>`、根式 `<m:rad>`）。
  - 正文中的几何顶点、变量字母（如 $A, B, C, P, Q, x, y, k$）统一设为 `Times New Roman` **斜体**（`<w:i/>`），数字、单位、括号与运算符设为 `Times New Roman` **正体**，中文设为 `宋体` 正体，**中文与字母/数字之间严禁添加多余空格**。

### 3. 纯粹“学生视角”原则（严禁剧透与教案化标签）
- **零剧透留白**：学生学案是供学生课前预习与课堂动笔书写的载体。所有填空处（`____`）、作图网格、表格数据格必须保持空白，**严禁将答案（如把 `S矩形AOBQ = ____` 直接写成 `|k|`）预先填入学生学案**。
- **零教师说教标签**：学案优化应聚焦于**修正错别字**（如 `两只曲线` $\to$ `两支曲线`）、**补全残缺句式**（如 `是由    。` $\to$ `是由________组成的。`）、**剔除语病**（如 `在一个任意一个` $\to$ `在任意一个`），严禁擅自往学生学案中塞入 `【温故知新】`、`【易错警示】`、`【方法指导】` 等教案风格的提示框。

### 4. 原题配图 300 DPI 高清重绘与裁剪框（`a:srcRect`）精准适配
- **300 DPI 出版级重绘**：使用 `ExamFigure` 引擎将原文档中低分辨率、带扫描底灰或文字重叠的配图重绘为宽度 $\ge 2400\text{px}$（300 DPI）的白底高清 PNG，直接覆盖 `word/media/image*.png`。
- **关键避坑点**：
  1. **读取 `<a:srcRect>` 裁剪参数**：Word 中许多内嵌图片带有 `<a:srcRect l="..." t="..." r="..." b="..."/>` 裁剪属性。重绘替换图片时，要么按原图的画布留白比例精确对齐有效内容区，要么将 `<a:srcRect>` 重置为 `0`，否则新图边缘会被 Word 裁切。
  2. **坐标轴刻度数字避让双曲线分支**：当绘制反比例函数双曲线时，坐标轴刻度数字应放置在**无曲线经过的象限侧**（例如 $k>0$ 曲线在第一、三象限时，刻度标在第二、四象限侧；$k<0$ 曲线在第二、四象限时，刻度标在第一、三象限侧），彻底杜绝负号或刻度数字与双曲线压线重叠。
  3. **图内分式必须上下叠置**：图片中的函数解析式（如 $y=\frac{2}{x}, y=-\frac{4}{x}$）严禁写成 `y = 2/x`，必须绘制为分子居中在上、水平分数线居中、分母居中在下的标准二维分式。

## 第二部分：交互式 HTML 动态讲解课件（希沃大屏版）设计规范

针对课堂投影与希沃白板（Seewo）触控场景，我们确立了**“四层全屏弹性架构 + 五大自适应题型版式（Layouts A–E） + 零剧透分步推导 + 零延迟荧光笔批注”**的完整标准。

### 1. 满屏无滚动四层弹性架构（`100vw × 100vh`）
课件严格锁定单屏高度（`overflow: hidden`），由上至下分为四层：
1. **顶部导航栏（`.topbar`，`52px`）**：左侧显示课程标题与当前模块胶囊，右侧集成 **`💡 知识回顾` 弹窗按钮**、**页码计数器**、**`🖍️ 荧光笔` 工具栏**（支持红/橙/蓝/绿四色半透明马克笔、橡皮擦、清空当前页批注）及 **`⛶ 全屏`** 按钮。
2. **主舞台（`.stage-wrap`，`flex: 1`）**：承载当前幻灯片卡片（`.slide-card`），内部分为头部标题区（`.slide-head`）与自适应内容区（`.slide-body`）。
3. **底部单行横向题目导航栏（`.bottom-nav`，`46px`）**：所有幻灯片切换按钮必须呈**单行横向排列**（`white-space: nowrap; overflow-x: auto`），严禁换行折成两排挤压主舞台高度。
4. **浮动激光翻页/推导胶囊（`#laser-float`）**：悬浮于右下角，包含 `◀ 上一页`、`▶ 下一步`（蓝色脉冲高亮，驱动同一题内的分步推导与画布联动）、`🔄 重置本页`、`下一页 ▶`。

### 2. 五大自适应题型版式（Layouts A–E）
根据每道题目的真实结构（是否有几何图、是否有选项图、是否为列表描点作图题），严禁生搬硬套单一布局，必须按需匹配以下 5 种标准版式：

| 版式代号 | 适用题型场景 | 空间分配与排版结构 | 典型代表题目 |
| :--- | :--- | :--- | :---
| **版式 A (`layout-a`)** | **无图纯文字/代数/概念辨析题** | **上题下解（100%全宽）**：上方全宽展示题干与选项网格（`.opt-grid`），下方全宽展示分步推导卡片。**严禁为了凑左右分栏而在左侧捏造无意义的假表格！** | 《2.2.2》新知应用第2题（`2025·浙江` $y=-\frac{7}{x}$ 性质辨析） |
| **版式 B (`layout-b`)** | **单配图几何/函数综合题、图形探究题** | **严格左解右图（左 `.screen-notes` + 右 `.screen-media`）**：左侧上方放题干与选项，下方纵向流式排列分步解析；右侧全高展示高对比度交互式 SVG 坐标系或几何画板。 | 《2.2.2》情境引入、问题1、追问1/2、$k$ 的几何意义、新知应用第1/3/4/5/6题、分层训练第1/2题 |
| **版式 C (`layout-c`)** | **含4个函数图象选项的选择题** | **上题与放大选项图 + 下分步解析（100%全宽）**：上方全宽展示题干及一行4张高清晰度 SVG 选项图卡片（点击或推导至最后一步高亮正确项），下方全宽展示排除法推导步骤。 | 《2.2.1》新知应用第1题、第6题（双函数同坐标系共存辨析） |
| **版式 D (`layout-d`)** | **列表—描点—连线作图探究题** | **上全宽表格 + 左下分步解析 + 右下交互式坐标纸**：顶部全宽展示带两端省略号 `…` 的取点表格（初始隐藏 $x, y$ 数值，点击“下一步”才同步填入表格并在右下坐标系描点连线）。 | 《2.2.1》问题1（画 $y=\frac{4}{x}$）、问题2（画 $y=-\frac{4}{x}$） |
| **版式 E (`layout-e`)** | **多点坐标验算/判断卡片题** | **上题干 + 下全宽卡片网格**：下方并排展示多个待验算点的交互卡片，随步骤逐张翻开计算乘积 $xy$ 是否等于 $k$。 | 《2.2.1》新知应用第2题（判断三点是否在图象上） |

### 3. “一题一页”与追问独立成页规范
- **拒绝多题挤占同一页**：每一道例题、练习题乃至每一个“追问（`追问1`、`追问2`）”都必须拥有独立的幻灯片页面，确保字号充足（题干 $\ge 1.05\text{rem}$，推导正文 $\ge 0.98\text{rem}$），后排学生清晰可见。
- **追问页顶部必配`【关联前问总结】`**：由于追问独立成页，为保持课堂思维连贯性，每个追问页的 `.screen-notes` 顶部必须放置一张浅灰蓝底色的 `【关联前问总结】` 提示卡，一句话凝练前问的核心结论，再自然引出本页追问。

### 4. “零剧透（Zero-Spoiler）”课堂教学节奏控制
1. **初始状态（`step = 0`）绝对纯净**：
   - 进入任何题目页时，所有推导步骤（`.step-item`）默认全部隐藏（`display: none`），选择题不标绿正确选项，填空题横线保持留白。
   - **无配图题的辅助坐标系防剧透铁律**：对于原学案中没有配图、但课件为了体现“数形结合”而在右侧提供了坐标系的题目（如《2.2.2》新知应用第5题“三点比大小”、分层训练第1题“区间最值求参”），**在 `step = 0` 初始状态下，右侧画布只允许显示空白平面直角坐标系（坐标轴、网格与刻度），严禁提前画出双曲线或描出点坐标**！必须等教师点击 `▶ 下一步` 推导出 $k$ 的正负号后，画布才同步动态绘出对应象限的双曲线分支与特征点。
   - **有配图几何题的辅助线防剧透铁律**：在 `step = 0` 时，右侧 SVG 严格还原原题配图；涉及“拉窗帘同底等高转化（连接 $AO$）”或“一线三垂直相似（过 $A, B$ 作 $x$ 轴垂线）”等辅助线及数字角标注（$\angle 1, \angle 2$），必须在点击 `▶ 下一步` 进入对应步骤时才以醒目彩色虚线动态浮现。
2. **按钮文案零剧透**：底部浮动按钮统一显示为简洁的 `▶ 下一步`（完成后变为 `✓ 推导完毕`），不显示 `(0/4)` 等暴露总步数的后缀。
3. **剔除画布底部冗余状态栏（Zero Redundancy）**：
   - 标题 `<h2>` 中严禁重复左侧 `.tag` 已有的模块前缀（如 `.tag` 已写 `三、新知应用 · 第1题`，`<h2>` 只写 `第1题：利用 k 的几何意义求矩形面积`）。
   - 右侧 `.screen-media` 画布下方严禁再堆砌与左侧推导卡片内容重复的 `#readout` 或 `#metrics` 结论文字条，把 100% 视觉焦点留给纯净的几何图形与动态交互控件。

### 5. 零延迟荧光笔与表格防抖动细节
- **荧光笔零延迟绘制**：直接监听 Pointer Events 在顶层 `<canvas class="ink-canvas">` 上使用 `ctx.quadraticCurveTo` 实时渲染半透明荧光笔迹（`rgba(..., 0.32)`），仅在 `pointerup` 时将画布快照推入 `inkHistory` 数组，彻底消除移动端的卡顿与延迟。
- **表格与卡片防抖动**：所有表格统一设置 `table-layout: fixed`，高亮单元格时使用 `box-shadow: inset 0 0 0 2px #2563eb` 替代修改 `border-width`，确保切换步骤时页面布局纹丝不动。
- **SVG 内置标准二维分式**：SVG 画布中的所有分式解析式（如 $y=\frac{2}{x}, y=-\frac{1}{x}, S=\frac{1}{2}|k|$）一律采用上下 `<text>` 加中间 `<line>` 渲染为标准叠置分式，严禁出现斜杠 `2/x`。

## 第三部分：多智能体（Multi-Agent）并行提速流水线

当面对包含多张配图重绘与十余页交互式幻灯片编写的综合任务时，标准作业程序（SOP）如下：
1. **阶段一（学案体检与配图重绘）**：扫描原 `.docx` 的 XML 结构，定位全部 `<w:object>`、`<a:blip>`、`<wp:anchor>` 浮动框与错漏文本，批量生成 300 DPI 高清配图并逐张视觉核验（检查是否有文字压线或裁剪截断），原地修补生成优化版 `.docx`。
2. **阶段二（分块并行编写课件脚本）**：将课件按教学环节拆分为 3 个独立 JS 模块（`chunk1_intro_explore.js`、`chunk2_apply*.js`、`chunk3_train_summary.js`），通过 `invoke_subagent` 并发启动 3 个子智能体同步编写各页 HTML 模板与 SVG 交互引擎。
3. **阶段三（一键编译与语法校验）**：调用 `build_courseware.py` 注入公共 CSS/JS 底座并自动执行 `node -c` 语法检查，秒级输出单文件零依赖的 `_动态讲解课件.html`。
